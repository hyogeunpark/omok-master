# 데일리 퍼즐 스펙

> 하루 한 문제, 모두가 **같은 문제**를 푸는 수읽기 퍼즐. 결과를 공유해 유입 경로를 만든다.
> 스트릭 개념은 [streak.md](streak.md), VCF 탐색은 [ai.md §3-5](ai.md), 금수는 [forbidden.md](forbidden.md) 참조.

## 1. 목적

- **리텐션**: "오늘 문제 풀었나?" — 매일 돌아올 이유를 만든다.
- **유입**: 결과 공유가 서버·계정 없이 작동하는 **유일한 바이럴 루프**다([003 ADR](../decisions/003-online-ranking-deferred.md)).
- 사용자가 0명이어도 성립한다. 랭킹과 달리 모수가 필요 없다.

## 2. 문제 형식

**"이기는 한 수를 찾아라"** — 주어진 국면에서 **강제승으로 이어지는 착수점 하나**를 고른다.

- 푸는 사람은 항상 **흑**이다. 금수([forbidden.md](forbidden.md))가 적용되므로 금수 자리는 정답이 될 수 없다.
- 정답은 **복수**일 수 있다(여러 착수점이 강제승이면 모두 인정).

### 2-1. 자명한 국면 제외

다음 국면은 **문제로 쓰지 않는다.** 읽을 것이 없어 퍼즐이 성립하지 않는다.

- **흑이 지금 당장 5목을 만들 수 있는 국면** — 열린 4가 이미 있는 상태가 대표적이다. "빈칸에 5번째 돌을 놓기"는 수읽기가 아니다.
- **정답이 4곳 이상인 국면** — 아무 데나 둬도 이기는 국면은 변별력이 없다.

즉 문제는 **강제 수순(VCF)을 새로 시작해야 하는 국면**만 채택한다.

### 2-2. 난이도

강제승까지의 수순 길이(VCF 탐색 깊이)로 구분한다.

| 난이도 | 기준 |
|--------|------|
| `easy` | 1수 VCF — 한 번의 강제 수로 승부가 갈림 |
| `normal` | 3수 이내 VCF |
| `hard` | 5수 이내 VCF |

## 3. 문제은행 (사전 생성)

퍼즐은 **런타임에 생성하지 않는다.** 품질이 보장되지 않고, 사용자마다 다른 문제가 나오면 공유가 성립하지 않는다.

### 3-1. 생성 방식

- 오프라인 스크립트 `scripts/puzzles.mjs`로 생성한다(Node 직접 실행, [ai-arena.md](ai-arena.md) 관례).
- Arena([ai-arena.md](ai-arena.md))로 대국을 돌려 실제 국면을 수집하고, 각 국면에 `vcfSearch`를 적용해 **강제승이 존재하는 국면만** 채택한다.
- 채택 조건:
  - 흑이 둘 차례이고, 강제승 착수점이 존재한다.
  - 해당 착수점이 **금수가 아니다**.
  - 돌이 너무 적거나(6개 미만) 많지 않다(40개 초과 제외) — 읽는 재미가 있는 국면만.
  - **§2-1의 자명한 국면이 아니다** (즉시 5목 가능 / 정답 4곳 이상 제외).
- 한 대국에서는 **최대 2문제**만 채택한다. 같은 판의 인접 국면은 서로 비슷해, 연속된 날에 비슷한 문제가 나오는 것을 막는다.
- 생성 결과는 `src/puzzles/bank.json`으로 저장해 **번들에 포함**한다. 서버 요청 없음.

### 3-2. 데이터 형식

```json
{
  "version": 1,
  "puzzles": [
    { "id": "p0001", "b": [[7,7],[8,8]], "w": [[7,8]], "solution": [[6,6]], "difficulty": "normal" }
  ]
}
```

- `b` / `w`: 흑·백 돌의 `[row, col]` 목록(좌표 배열로 용량 절약).
- `solution`: 정답 착수점 목록. 하나라도 맞으면 정답.
- 차례는 항상 흑이므로 별도 필드를 두지 않는다.

### 3-3. 문제 추가는 이어붙이기(append)

문제 선택이 `(번호-1) % 문제수`이므로, **기존 문제의 순서가 바뀌면 날짜↔문제 대응이 전부 어긋난다.** 구 번들을 캐시한 사용자와 새 번들을 받은 사용자가 같은 날 다른 문제를 보게 되어 결과 공유가 무의미해진다.

- 문제 추가는 **기존 배열의 순서를 보존한 채 뒤에 이어붙인다**(기본 동작).
- 이미 있는 국면은 **중복 제거**한다(흑·백 돌 배치가 같으면 동일 문제로 본다).
- 전체 재생성은 `--fresh`를 **명시할 때만** 허용한다. 실수로 덮어쓰는 것을 막는다.

> 이어붙이기는 소진 이전 구간(`번호 ≤ 기존 문제수`)의 대응을 바꾸지 않는다. 나머지 연산이 그 구간에서는 감싸지 않기 때문이다.

### 3-4. 자동 생성 (GitHub Actions)

소진(§4-1)을 미리 막기 위해 문제은행을 **주기적으로 늘린다.**

- 워크플로 `.github/workflows/puzzles.yml`이 **매월 1회** 실행된다(수동 실행도 가능).
- 생성 → 이어붙이기 → 새 문제가 있으면 **Pull Request를 연다.**
- **main에 직접 push하지 않는다.** 두 가지 이유다.
  1. `GITHUB_TOKEN`으로 만든 push는 다른 워크플로(배포)를 트리거하지 않는다.
  2. 기계 필터를 통과해도 퍼즐로 부적절한 문제가 섞일 수 있다(§2-1의 교훈). **사람의 검수 단계**가 필요하다.
- PR 본문에는 새로 추가된 문제 일부를 **보드 그림으로 렌더**해 훑어볼 수 있게 한다.

## 4. 오늘의 문제 선택

- **날짜 → 문제 인덱스**를 결정적으로 매핑한다. 같은 날이면 모든 사용자가 같은 문제를 받는다.
- 기준 날짜(`2026-07-27`)를 **#1**로 하고, 로컬 날짜 기준 경과 일수를 문제 번호로 쓴다.
- 인덱스는 `(번호 - 1) % 문제수`로 순환한다.

### 4-1. 이미 푼 문제의 대체

은행이 순환하면 **개근한 사용자에게는 이미 푼 문제가 다시 배정된다.** 답을 아는 문제는 퍼즐이 아니다.

- 날짜로 배정된 문제를 **그 사용자가 이미 푼 적이 있으면**, 아직 풀지 않은 문제 중 하나로 **대체**한다.
- 대체 문제도 **결정적으로** 고른다 — 미완 목록에서 `문제 번호 % 미완 개수`로 선택해, 같은 사용자가 같은 날 다시 열어도 같은 문제가 나온다.
- 모든 문제를 다 푼 경우에는 날짜 배정 문제를 그대로 낸다(대체 불가).

> **기본은 어디까지나 날짜 매핑이다.** 대체는 겹칠 때만 일어나므로, 대부분의 사용자는 같은 날 같은 문제를 받고 결과 공유의 비교 가능성이 유지된다.
> 근본 해법은 **문제은행을 계속 늘려 순환 자체를 막는 것**이다(§3-3).

## 5. 진행 규칙

- **고른 자리에는 흑돌을 놓아 보여준다.** 눌렀는데 아무 변화가 없으면 입력이 됐는지 알 수 없다.
  - **정답**이면 그 돌을 그대로 둔다 — 이기는 수가 국면에 남아야 왜 이기는지 보인다.
  - **오답**이면 잠시 보여준 뒤 되돌린다. 틀린 돌이 남으면 다음 시도의 국면이 달라져 혼란스럽다.
- **시도 3회**. 오답이면 남은 횟수를 표시하고 다시 고른다.
- 3회 모두 틀리면 **정답을 공개**하고 실패로 기록한다.
- 정답을 맞히면 즉시 성공으로 기록하고 결과 화면을 보여준다.
- **하루에 한 번만** 푼다. 이미 푼 날은 결과 화면을 다시 보여주고, 재도전은 불가하다.
- 금수 자리를 고르면 오답으로 처리하되, **금수임을 알려준다**(학습 효과).

## 6. 기록 / 퍼즐 스트릭

대국 출석 스트릭([streak.md](streak.md))과 **분리**한다. 퍼즐을 푼 것과 대국을 둔 것은 다른 행동이다.

- 저장 키: `omok_puzzles` (localStorage). 형식: `{ "YYYY-MM-DD": { solved: boolean, attempts: number, id: string } }`.
- `id`는 그날 실제로 푼 문제의 ID다. **어떤 문제를 이미 풀었는지** 판정해 §4-1 대체에 쓴다. 이 필드가 없는 기존 기록은 "어떤 문제인지 모름"으로 간주하고 대체 판정에서 제외한다(하위 호환).
- **퍼즐 스트릭**: `solved: true`인 날의 연속 일수. 판정 규칙(오늘/어제까지면 유지)은 [streak.md §2-1](streak.md)과 동일하며, **같은 날짜 연속 판정 로직을 공유**한다.
- 실패한 날은 스트릭이 끊긴다(푼 것이 아니므로).
- 최고 기록을 함께 보존한다.

## 7. 결과 공유

서버 없이 **클립보드 복사**로 동작한다. 정답 자체는 노출하지 않는다.

```
오목 퍼즐 #12
◆◆◇ 2번째 시도에 성공
퍼즐 5일 연속
https://hyogeunpark.github.io/omok-master/
```

- 시도 표시: 성공한 시도는 `◆`, 실패한 시도는 `◇`.
- 실패 시에는 시도 표시와 함께 실패임을 알린다.
- `navigator.clipboard`를 쓰되 실패하면 텍스트를 선택 가능한 형태로 보여준다(HTTPS가 아닌 환경 대비).

## 8. 진입 / 화면

- **시작 화면**([game-modes.md](game-modes.md))의 스트릭 배너 아래, 모드 카드 위에 **"오늘의 퍼즐" 카드**를 둔다.
- 카드에는 퍼즐 번호와 상태(미완료 / 성공 / 실패)를 표시한다. 이미 푼 날은 상태가 드러나 재진입 동기를 만들지 않는다.
- 퍼즐 화면은 기존 `Board`를 재사용하되, **착수는 정답 판정용**이며 대국으로 진행되지 않는다.

## 9. 구현

| 파일 | 역할 |
|------|------|
| `scripts/puzzles.mjs` | **신규** — 문제은행 생성(오프라인). 기본 이어붙이기, `--fresh`로 재생성 |
| `.github/workflows/puzzles.yml` | **신규** — 월 1회 자동 생성 → PR 생성 (§3-4) |
| `src/puzzles/bank.json` | **신규** — 생성된 문제은행(번들 포함) |
| `src/engine/puzzle.js` | **신규** — 날짜→문제 선택, 정답 판정, 퍼즐 기록/스트릭 (순수 JS) |
| `src/engine/streak.js` | 날짜 연속 판정 로직을 퍼즐과 공유하도록 정리 |
| `src/ui/PuzzleScreen.jsx` | **신규** — 퍼즐 화면 |
| `src/ui/StartScreen.jsx` | 오늘의 퍼즐 카드 |

`engine/puzzle.js`는 React/DOM 비의존 순수 JS로 작성한다.

## 10. 완료 기준 (Acceptance)

- 같은 날짜에는 항상 같은 문제가 선택되고, 날짜가 바뀌면 다음 문제로 넘어간다.
- 정답 착수점을 고르면 성공, 3회 오답이면 실패로 기록된다.
- 금수 자리는 정답으로 인정되지 않는다.
- 이미 푼 날은 재도전할 수 없고 결과가 그대로 보인다.
- 퍼즐 스트릭이 대국 출석 스트릭과 **독립적으로** 집계된다.
- 문제은행의 모든 문제는 정답이 1개 이상이고, 정답 수는 금수가 아니다.
- **이미 푼 문제가 배정되면 아직 풀지 않은 문제로 대체되고, 그 선택은 결정적이다**(§4-1).
- 모든 문제를 푼 사용자에게는 날짜 배정 문제가 그대로 나온다.
- **이어붙이기는 기존 문제의 순서와 소진 이전 구간의 날짜 대응을 바꾸지 않는다**(§3-3).
